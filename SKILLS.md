# LingoSnap AI Development Skills (Single Source of Truth)

## 1. Product Definition & Core Concept

**LingoSnap** is a visual language learning application that helps users remember vocabulary and sentences through **one contextual image**.

Users study independently through visual anchors and spaced repetition.

### Core Learning Concept:
```
One situation image
+
One target vocabulary
+
One example sentence
+
Pronunciation
+
SRS review
```

### Main Learning Flow:
```
Image
↓
Guess the meaning
↓
Reveal vocabulary
↓
Learn pronunciation
↓
Read example sentence
↓
Practice quiz
↓
SRS review
```

---

## 2. Product Philosophy

Images are memory anchors. The goal is not simple translation memorization.

The core learning sequence:
$$\text{Image} \longrightarrow \text{Meaning} \longrightarrow \text{Usage} \longrightarrow \text{Long-term memory}$$

Every vocabulary item must connect:
1. **Visual context**: Situation image representing actions/real-world context
2. **Word**: Target vocabulary
3. **Native meaning**: Direct translation/meaning
4. **Example sentence**: Practical usage in context
5. **Pronunciation**: BCP-47 TTS & phonetic guides

---

## 3. Content Model & Image Rules

Vocabulary is the core learning unit.

```
Situation Image
      │
      │
  Vocabulary
      │
      │
   Sentence
```

### Image Rules:
- Images are managed as **structured learning content**, not dynamically generated by Vision AI on every turn.
- **Sources**: Manual upload, Image generation API (pre-generated), External image provider.
- **Visual Focus**: Images must represent **actions**, **situations**, and **real-world context** (e.g., A person performing an action like a child eating an apple, a person running in a park).
- **Avoid**: Isolated dictionary-style object images or meaningless abstract illustrations.

---

## 4. Database Rules (Supabase PostgreSQL)

Use the existing **Supabase PostgreSQL** database architecture with Row Level Security (RLS). Do not introduce Firebase.

### Main Entities:
- **`study_vocabularies`**: Stores vocabulary information, meanings, pronunciations, and example sentences. *(Live reference table)*
- **`ai_lessons`**: Stores learning sessions and contextual image references.
- **`ai_lesson_vocabulary`**: Connects lessons and vocabulary items with visual bounding box targets.
- **`ai_quizzes`**: Stores quiz sessions.
- **`ai_quiz_questions`**: Stores individual quiz questions, options, and correct answers.
- **`ai_user_progress`**: Stores learning progress, daily streak, and XP.
- **`ai_review_items`**: Stores SRS scheduling, interval stages, and review timestamps.

### Excluded Features:
Remove all assumptions and tables for: partner matching, language exchange, chat, friends, social learning, or real-time communication.

---

## 5. AI Usage Rules

AI is **optional** and used for content generation pipeline, **NOT called during normal user learning sessions**.

- **Normal Learning**: Serve pre-generated/cached lessons from Supabase for zero latency and cost efficiency.
- **AI Utility**: AI can assist offline/batch generation of:
  - Example sentences
  - Image generation prompts
  - Quiz questions
- **Content Saving**: All generated content must be saved to the database and reused.

## 6. Architecture Rules

Follow the existing Feature-Based Layered Clean Architecture:
$$\text{Presentation (UI)} \longrightarrow \text{Application Services} \longrightarrow \text{Domain Repositories} \longrightarrow \text{Infrastructure}$$

### Mandatory Reuses:
- Supabase client (`src/infrastructure/supabase/client.ts`)
- Repository pattern (`IAuthRepository`, `IStudyRepository`, etc.)
- Client State (Zustand) & Server State (TanStack Query)
- Existing SRS scheduling logic (`user_studied_words` / `ai_review_items`)

Do not rewrite or refactor unneeded parts of the application.

---

## 7. UI Rules

The learning experience must be **Simple**, **Visual**, and **Beginner-Friendly**.

### Main Learning Screen Layout:
```
Large Image (Situation Anchor)
↓
Vocabulary (Word & Meaning)
↓
Example Sentence
↓
Audio Button (Pronunciation)
↓
Quiz (Practice)
```

### Avoid:
- Chat UI / Inbox
- Social feeds & Partner profiles
- Complex multi-step dashboards

---

## 8. Development Rules

Before changing code:
1. Read `SKILLS.md`
2. Inspect existing implementation
3. Reuse existing components in `src/shared/components/` (`Button`, `Card`, `AppSheet`, `Toast`, `Typography`)
4. Keep the application buildable (`./node_modules/.bin/tsc --noEmit` clean)

Every change must:
- Explain affected files clearly
- Maintain architectural consistency
- Avoid unnecessary external dependencies
